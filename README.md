# 炎都拾光

给两个人用的微信小程序。现在能用的是：微信登录、互相确认对象、女性经期和排卵推算、纪念日、生日、小日程、心愿、一起决定、时光胶囊、首页天气、按生日生成的今日建议、课程表、法定节假日与调休，以及按每条记录自己的时机下发订阅消息提醒。首页的卡片可以长按管理，自己决定放哪几张、按什么顺序。相册、足迹、年度回顾在「我」里只有分段和空状态，还没有内容。

不发布正式版。只有管理员、项目成员和体验成员能打开体验版。

## 打开之前

1. 用微信开发者工具打开本目录。云环境 ID 在本机的 `miniprogram/app.js` 里配置，不要写进 README 或其它公开文档。
2. 在 `cloudfunctions` 上右键，先选云环境，再在 `api` 上选择「创建并部署：云端安装依赖（不上传 node_modules）」。
3. DeepSeek 密钥和和风天气放在 `cloudfunctions/api/secret.js`。和风要填 API Host，以及 `QWEATHER_PRIVATE_KEY`（和已保存公钥成对的私钥全文，多行时用反引号包住）。这个文件已在 `.gitignore`，不进 Git。改完云函数后要重新部署，手机上才会生效。
4. 云数据库集合会在云函数第一次成功调用后出现：`users`、`periods`、`anniversaries`、`birthdays`、`schedules`、`wishes`、`decisions`、`capsules`、`timetables`、`subscriptions`、`readings`、`asks`、`memories`、`notes`、`holidays`。权限选「仅管理端可读写」。改完云函数后要重新部署。
5. 提醒要配模板才发得出去。推荐让云函数自己去拉，不用手抄：在云开发控制台给 `api` 云函数加环境变量 `WX_APPSECRET`（微信后台「开发管理 → 开发设置」里的 AppSecret）。有了它，云函数会用 `WX_APPID`（不填则用本项目的 appid）换 access_token，再去读「我的模板」，连同每个模板关键词的真实 key 一起拿到，按模板标题自动对上日程 / 留言 / 经期 / 生日 / 纪念日 / 决定 / 胶囊 七个场景。
6. 想手动指定也可以，加环境变量 `SUBSCRIBE_TEMPLATES` 覆盖，优先级最高：
   `{"schedule":{"id":"模板ID","fields":["thing1","thing2","date3","thing4"]}}`，`fields` 要和模板里关键词的顺序一致。
7. 配好之后，小程序「我的 → 提醒设置」每一项都能点「+1」攒额度、点「试一条」真发一条。发不出去会直接告诉你原因（模板 ID 不对 / 关键词对不上 / 没额度）。想看每个场景最终对上了哪个模板，在云开发控制台调一次 `getSubscriptions`，返回的 `templates` 里每个场景都带着它配上的 `templateId`。
8. `cloudfunctions/api/config.json` 里已经开好 `subscribeMessage.send` 权限，以及每小时整点跑一次的定时触发器（`0 0 * * * * *`）。触发器随云函数一起部署。建议顺手把环境变量 `SUBSCRIBE_STATE` 设成 `formal`（默认 `trial`）。
9. 体验版在 mp.weixin.qq.com 的「管理 → 版本管理」里选择。体验二维码大约 7 天过期，过期后重新生成，不用重新选体验版。
10. 位置只用于查天气。隐私指引里要声明位置信息并填写用途。没有定位时，首页可以手选城市。

## 文件是干什么的

- `miniprogram/app.js`：启动云开发，并用 `call` 调用云函数。
- `miniprogram/app.json`：页面名单、导航颜色、位置隐私声明。
- `miniprogram/app.wxss`：单独打开的页面用的底色、卡片和按钮。嵌在首页里的三个面板要用自己的样式。
- `miniprogram/components/weather-icon`：天气图标。晴、多云、雨、雪、雾、雷六种都用样式画出来，跟着传入的尺寸缩放，压在天空上也看得清。传 `tone`（day/dawn/dusk/night）就按时段换样子：夜里晴天出月亮，日出日落时是半轮压在地平线上的太阳，夜里多云是云角上探出月亮。
- `miniprogram/pages/main`：底部标签所在的滑动页。左右滑在首页、日历、聊天、记录、我之间切换。页面底色是原来的暖白色，天空只画在首页的天气卡片里。
- `miniprogram/pages/home`：卡片式首页，从上到下是自己排好的卡片：问候、今天的课、天气、对方留下的一句话、今日建议、生活提醒、临近安排。长按任意卡片进入管理：✕ 移除、拖 ☰ 换顺序、下面「＋ 添加卡片」把移除的加回来，顺序和增减都记在本机、按微信账号分开。天气卡片整张是一块天空，晴、多云、风、雨、雪、雾、雷雨和晚上都铺满卡片，字浮在天空上面。横滑卡片或上下快滚会让风变大；雨点落到底边会溅出水花；雪天边框上会慢慢积雪，抹一下下边框就能擦掉；雾天点一下能擦开一团雾。每小时那一行的图标跟着当时的天色走：白天大太阳，黄昏是落日，入夜换成月亮。长按温度可以预览天气动画：先挑一种天气，再挑白天／日出／日落／夜里，八种天气配四个天色都能看全，再点一次同一个天色就跟回真实时间。今日建议超过 1 小时才重新生成。
- `miniprogram/pages/timetable/index`：课程表。**整周铺开**：一行七天（周末两天整周都没排课就只留周一到周五），首列是时间和节次，右边周一到周日；周五和周六之间留一道空隙、周六日的表头换个底色，一眼能分清工作日和周末。左右两侧各有一列时间，左边那列管周一到周五；周六日如果有自己的一套作息，右边就再长出一列，专写周末那几节几点上——两边对称，看时间不用来回找。两套节次**先按分组分桶、再在组内对齐**，所以周末少几节也不会把晚自习错排到下午去。分组按「早自习 / 上午 / 下午 / 晚自习」分段显示；上午和下午总会显示，其它分组（含自己加的「午休」「课间操」）整周没课就整块收起。没课的格子是空的虚线，点任意一格弹输入框，写什么都行：学生写科目、老师写班级。**同样的文字自动配同一个颜色**，方便一眼看出哪几节是同一门；弹层里点色点能换色，还能选是「只改这一格」还是「所有同名的」。今天那一列的表头是实心粉色，法定假日的日期右上角标「休」、调休标「班」，本周有哪些休/班日在上面汇总一行。两个人互为对象时都能改同一份。开了回家周就多一行「本周 上课 / 回家」，点一下可以单独改这一周。
- `miniprogram/pages/timetable/settings`：课程表设置。谁能看（双方可见 / 仅自己）、回家周（每 N 周的第 K 周回家，基准周自己挑，改过的周可以一键清空）、分组、以及节次表。分组默认「早自习 / 上午 / 下午 / 晚自习」，点名字能改，能加自己的（最多 8 个，比如「午休」「课间操」），分组下还有节次时不允许删；列表顺序就是课表页的显示顺序。节次表有名称、起止时间、分组（点分组那两个字按你的分组顺序循环切）、上下移、删除、一键生成默认节次。时间可以直接打字（`6:40`、`0640`、`640` 都认，会归一成 `06:40`），也可以点 ▾ 用滚轮。节次分两套：「周一到周五」和「周六周日」，标签上直接写着各几节。周末默认跟工作日共用同一套，要不一样才打开「周末单独排」——打开时会把工作日那份复制过来，你再删改。周末不排课的话，课表页那两列会自动收起，打开「周末单独排」就回来了。
- `miniprogram/pages/calendar`：月历、农历、事项图标、节假日「休 / 班」角标、今年的黄历宜忌，以及临近安排（含节假日）。点某一天能看到假期区间和调休安排。黄历在手机上计算，不请求模型。
- `miniprogram/pages/records`：纪念日、生日、经期、日程、心愿放在一页，右上角「+」添加、「管理」多选删除，可以筛选类型，按日期或类型排序。顶部是「一起决定」：双方各投一票，可以按票数定或随机定，两台手机看到同一个结果。
- `miniprogram/pages/mine`：头像、昵称、对象状态，右上角是编辑和设置；下面是相册、时光胶囊、足迹、年度回顾四段，时光胶囊可以封存和到期打开。
- `miniprogram/pages/profile`：昵称、性别、对象和称呼、经期提醒（提前几天、几点），以及阳历或农历生日、时辰、出生地。
- `miniprogram/pages/partner`：选择或取消对象。双方都确认后才互相看见。
- `miniprogram/pages/settings`：设置页，分成三组：权限（位置）、订阅推送（进提醒设置）、数据安全（清空自己的数据）。
- `miniprogram/pages/notify`：提醒设置。7 类提醒各自一个开关、系统授权状态、剩余条数、「+1」和「试一条」。关掉某项后不再申请也不再推送，已攒的条数保留。「试一条」会用真实模板发一次，配错了当场就能看到原因。
- `miniprogram/components/remind-picker`：提醒时机的三列选择器（日期 / 时 / 分），日程、生日、纪念日、胶囊、经期共用。日期列按目标日排出来，选中后换算成「提前几天」存库。
- `miniprogram/pages/ask`：AI 聊天面板（嵌在主页 swiper 中间）。按文字量显示以往对话，右上角可以改记忆，也可以多选删除聊天记录。说一句带日期的事，AI 会先给一张确认卡，点「记下」才写进日程；问最近安排会去查日程、纪念日和阳历生日。模型不会直接写库。
- `miniprogram/utils/date.js`：日期加减、纪念日在闰年的处理，以及「今年这个日子过了就取明年」。
- `miniprogram/utils/remind.js`：提醒时机的规范化和三列滚轮的组装/解析，`{ enabled, leadDays, hour, minute }` 只有这一种形状。
- `miniprogram/utils/subscribe.js`：一次性订阅。模板 ID 由云端的 `getSubscriptions` 下发，点「+1」时在点击回调里同步发起 `requestSubscribeMessage`，只把 accept 的回报给云端加额度。
- `miniprogram/utils/birthday.js`：计算现在多少岁，以及距离下一次生日还有几天。阳历和农历都可以。
- `miniprogram/utils/cycle.js`：经期、排卵和易孕期的推算。
- `miniprogram/utils/filter.js`：月历筛选记在本机，按微信账号分开。
- `miniprogram/utils/home-cards.js`：首页卡片的顺序和增减也记在本机。存的是「现在有哪几张」和「我主动删掉过哪几张」，这样以后新加卡片类型时不会硬塞回被删掉的位置。
- `miniprogram/utils/lunar.js`：生日滚轮和月历农历。换算用 `utils/lunar-lib.js`（lunar-javascript 1.7.8，MIT）。
- `miniprogram/utils/almanac.js`：黄历宜忌。1920–2100 范围内任何一年都能算，不是只有今年。
- `miniprogram/utils/festivals.js`：**节假日与节日，全项目只在这里维护**。阳历节日、农历节日、法定节假日和调休都在这。法定节假日是项目里唯一会过期的数据，见下面「需要你手工维护的东西」。
- `miniprogram/utils/sky.js`：天气卡片的时段、配色和粒子。画布铺满整张卡片，文字压在画布上面。
- `cloudfunctions/api/index.js`：唯一的云函数。按 `action` 处理登录、资料、对象、经期、纪念日、日程、心愿、一起决定、时光胶囊、课程表、节假日、订阅额度、天气、今日建议、留言和追问；另外接管定时触发器，每小时按每条记录的提醒时机下发订阅消息。模板 ID 和关键词优先从微信接口自动读取（`WX_APPSECRET`），`SUBSCRIBE_TEMPLATES` 可手动覆盖。课程表一人一份存在 `timetables`，分组表（`groups`，最多 8 个，可改名可增删，节次上只存 key）和节次一起存；工作日和周末各有一套节次（周末那套为空就是跟工作日共用），每套上限 16 节、一周最多 200 节课，回家周按「每 N 周的第 K 周」轮换，也可以单独指定某一周。节假日存在 `holidays` 集合，每天凌晨 4 点自动抓取并写入（见下）。
- `cloudfunctions/api/config.json`：云调用权限（`subscribeMessage.send`）和每小时整点的定时触发器。
- 云端配置（环境变量）：`WX_APPSECRET`（拉模板，必填其一）、`WX_APPID`（默认用本项目的）、`SUBSCRIBE_TEMPLATES`（手动覆盖模板）、`SUBSCRIBE_STATE`（`trial` / `formal`）。
- `cloudfunctions/api/secret.js`：DeepSeek 密钥和和风天气密钥，只留在本机和云端。

经期记在女性名下。双方互为对象后，男方的月历上能看到，也能修改。纪念日和日程默认双方可见，也可以改成仅自己可见。

提醒都是「提前几天 + 几点」，默认早上 9 点。日程默认前一天，生日、纪念日、胶囊默认当天，经期默认提前 2 天。一次性订阅是「谁点谁收」，两个人要各自在「提醒设置」里攒额度；一方没额度只影响他自己，另一方照常收到，小程序里的内容也一直能看到。经期提醒女方推自己的记录，男方开了就推对象那本。

农历生日的提醒暂时不发，因为服务端没有农历表；界面上会写明。

课程表一人一份，第一次进去会先给一套默认节次（晨读 6:40-7:05、第 1–9 节、晚一、晚二，时间按常见作息排好），按自己学校的作息改就行。录法是三步：在设置页把节次和时间排对 → 点「保存」 → 回课表页点任意格子填科目或班级。课表整周铺开，一行就是一周，不用一天天点。周六日默认跟工作日共用同一套节次，也就是共用左边那一列时间；哪天作息真的不一样，再去「节次」里打开「周末单独排」——它会把工作日那份复制过来，你只改需要不同的地方。打开以后右边会多出一列时间，专管周六日，左边那列仍然只写工作日，两边对称，对照着看不会含糊。删节次只删当前这套。

**自动收起**：课程表按分组分段显示，分组默认是「早自习 / 上午 / 下午 / 晚自习」，在设置页的「分组」里可以改名，也可以加「午休」「课间操」这种（最多 8 个）。上午和下午是主体，永远显示；其它分组整周七天一格课都没有就整块收起，周六日两天整周没课也把这两列收起，只留周一到周五。想让它回来：去设置页把周末那套节次排上（打开「周末单独排」），或者给那个分组填一节课，回课表就自动出现。分组表存在你自己的课表里，两个人各有一份。

**谁能看**：设置页最上面可以选「双方可见」或「仅自己」，默认双方可见。双方可见时两个人看到和改的是同一份（自己没有课表时就显示对方那份，保存时回写那份的归属）；切成「仅自己」后，对方既看不到也改不到，首页的「今天的课」卡片同样拿不到，但你自己照常用。回家周没打开时，课表页完全不出现上课 / 回家这一层；打开了就按「每 N 周的第 K 周回家」推算，单独改过的那一周优先，可以一键清空手动调整。

法定假日那天，日期右上角标「休」，本周有哪些休/班日在课表顶部汇总一行，首页「今天的课」当天显示放假；调休上班日标「班」，课表内容照旧（国务院只规定哪天上班，补周几的课各校自己定，所以不替学校做决定）。整表只有回家周才淡显。

## 需要你手工维护的东西

一年后回来，照这张表检查就行。**除了第 1 条，其它都是「出问题才要动」，平时不用管。**

### 1. 法定节假日（唯一会过期、需要每年确认的）

| 项 | 说明 |
|---|---|
| 文件 | `miniprogram/utils/festivals.js` 里的 `BUILTIN_SPANS` |
| 什么时候 | 每年 11 月国务院公布**下一年**安排之后。平时云端每周会自动补，通常你什么都不用做 |
| 怎么知道要动手 | 翻到新的一年时，日历顶部出现「这一年（20XX）还没有节假日数据 · 上次更新 X月X日 · 点这里重试」。先点一下重试；还是不行再改文件 |
| 去哪拿 | ① 中国政府网 `www.gov.cn` 搜「国务院办公厅关于 XXXX 年部分节假日安排的通知」；② 直接看 `https://timor.tech/api/holiday/year/2027`（把年份换掉）；③ GitHub `NateScarlet/holiday-cn` |
| 怎么改 | 在 `BUILTIN_SPANS` 里按年份加一段，**一条假期一行**：`from`/`to` 是放假第一天和最后一天，`workdays` 是通知里明说要上班的调休日（没有就省略）。改完上传体验版 |
| 不更新会怎样 | 那一年日历只显示节日名、不标「休 / 班」，课表不提示放假。**其它年份和功能都不受影响**，不会报错 |

加一年的样子（照抄 2027 那段改日期即可）：

```js
  // ── 2028 ── 国办发明电〔2027〕X 号
  { name: "元旦", from: "2028-01-01", to: "2028-01-03" },
  { name: "春节", from: "2028-01-25", to: "2028-02-02", workdays: ["2028-01-22", "2028-02-04"] },
  { name: "清明节", from: "2028-04-04", to: "2028-04-06" },
  // …
```

**为什么还要留内置表**：云端抓不到时（境外源被墙、第三方接口挂了）它就是唯一的数据来源。它不需要你每年维护——云端补上了就用云端的，内置只是兜底。想彻底去掉也可以，删掉 `BUILTIN_SPANS` 内容即可，但那时断网/抓取失败就真的没数据了。

**云端是怎么自动补的**：云函数每天凌晨 4 点检查一次，7 天内只真正抓一次。抓取顺序是 `timor.tech`（境内，实测与官方原文逐日一致）→ jsDelivr → GitHub raw，任一成功就写进 `holidays` 集合；已有年份不覆盖。抓取在云函数里，跟你手机网络无关。想手动触发：日历页点提示文字，或在云开发控制台调一次 `syncHolidays`（带 `force: true`）。某一年数据想手工订正，直接在云开发控制台改 `holidays` 里对应年份的文档，前端下次刷新生效。

### 5. `miniprogram/utils/lunar-lib.js`（第三方农历库，基本不用动）

lunar-javascript 1.7.8（MIT）。**农历、闰月、二十四节气、黄历宜忌、四柱干支、生肖全都是它算出来的**，覆盖 1900–2100，不会因为过年而失效，也不需要每年更新。只有想升级库版本时才替换这个文件（压缩后 400 多 KB）。

### 7. 改天色代码后跑一下自测

首页天气卡那片天空（太阳升落、月亮轨迹、云雨雪雾、雪在边框上堆积）全是 canvas 手算的，算错了肉眼很难发现，所以配了一套自动检查：

### 哪些数据是算出来的、永远不会过期

免得以后误以为坏了：

| 数据 | 怎么来的 |
|---|---|
| 二十四节气 | `lunar-lib.js` 按天文算法算 `getJieQi()` |
| 农历、闰月 | 同上 |
| 黄历宜忌 | 同上，`getDayYi` / `getDayJi`（1920–2100 任意年都能算） |
| 四柱干支、生肖 | 同上 |
| 阳历 / 农历节日名 | `festivals.js` 里的固定表（元旦、春节、中秋…），不会变 |
| 生日可选年份 | 自动算到今年 |
| 天气、今日建议 | 实时请求，不缓存过期数据 |
| 订阅模板、access_token | 自动拉取 / 每 2 小时自动刷新 |
